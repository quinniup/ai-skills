# init-proj：共享 Agent 工作区初始化与迁移

## 目标与边界

建立“共享正文一个来源、工具专用薄适配、个人配置隔离”的工作区。适用于任意技术栈，不复制宿主仓库的 IoT、Java、角色花名册或本机路径。

`.agents/rules/roles/workflows/memory` 是本技能采用的项目约定，**不是所有工具都会自动加载的通用标准**。`AGENTS.md`、Claude 配置及 skills 的实际发现能力须结合工具和版本核对。普通链接是导航，不等于自动读取；文档不是可执行安全门禁。

执行前读取 [结构与职责](references/workspace-layout.md)、[迁移与验收](references/migration-checklist.md)。涉及任务记录布局、完成归档或长文档压缩时，另实际读取[任务生命周期](references/todo-lifecycle.md)及项目现有规则；沿用已有约定，不默认创建todos/archive、索引或空任务。[模板](templates/) 是需要填实的起点，不是批量覆盖文件的生成器。

## 模式

- **audit（默认）**：只读盘点，输出重复、冲突、忽略范围和建议目标；不改文件。
- **init**：新项目或尚无 Agent 配置；只建立有真实内容的最小入口，其他目录按需创建。
- **migrate**：已有配置集中归置；优先迁移、引用和兼容，保留独有要求与原始证据。

用户仅说“整理一下”“做个方案”时采用 audit；明确要求创建/初始化/迁移可视为对应范围的写入授权。新增删除、跨仓修改或外部知识库改动超出该范围时先确认。缺少会影响决策的信息才询问，不机械重复求确认。

## 工作流

### 1. 识别目标和保护基线

确认实际工作目录、仓库根、分支、工作树与未提交改动。记录目标工具、技术栈、已有知识库、角色及共享范围；未知命令不要编造。

用文件发现工具查找隐藏目录、嵌套入口、skills、rules、agents、hooks、settings；读取命中的现有文件和适用指令。检查符号链接及真实目标、Git 跟踪/忽略范围。大型文件必须分段读完整，重写前核对总行数，**不能将截断输出当完整正文**。

保留用户未提交内容、已有技能、hooks 和权限设置。不要执行 reset、clean、stash apply，或顺手整理业务代码。

### 2. 分类与提出方案

输出“现位置 → 目标 → 处理（保留/迁移/引用/兼容/作废待确认）”清单：

- 入口：仓库身份、必须读取和按任务读取的导航、已核实的常用命令。
- rules：跨工具约束；不把所有最佳实践升级为铁律。
- roles：职责、边界、验收要求；工具 frontmatter 与 permissions 留在适配层。
- workflows：通用协作流程；工具编排偏好留在该工具目录。
- memory：外部记忆导航及确认/维护要求，不复制知识正文。
- skills：可复用操作步骤及配套资源，已有技能保持不变。
- docs：人与 Agent 共用的开发、设计、契约及运维文档，不为“集中”搬进 Agent 目录。
- tasks：当前任务、已验收归档与历史证据分开；沿用项目资料目录，按[生命周期](references/todo-lifecycle.md)审查状态/验收、重复过程与引用，不把归档都当done。
- local：个人路径、权限、凭据、会话缓存；忽略、不提交。

存在冲突时披露证据，不用“根文件永远优先”代替事实核对。规则作废须留原因，不能静默丢失；历史路径保留当时含义。

### 3. 按授权落地

以 [结构约定](references/workspace-layout.md) 为目标；入口尽量简短（建议低于 200 行，不是硬格式限制），细节按任务加载。

先创建并验证新正文，再更新引用与薄适配，最后处理旧路径。角色适配必须明确要求实际读取共享正文，不能假定角色内 `@` 导入或普通链接会自动展开。

`CLAUDE.md` 可导入 `@AGENTS.md`，但若 AGENTS 当前链接到 CLAUDE，必须先解除自引用风险；涉及删/移动须核对绝对目标及符号链接，不能误写链接指向的原文件。不把普通文档命名为 claude.md：大小写不敏感文件系统可能把它视为指令入口。

修改 Git 忽略规则只放行已审查共享文件，个人设置继续忽略。新增 roles/skills 不代表工具已注册成功。外部仓库依赖旧路径时保留短迁移导航，不复制正文、不默认用目录符号链接；不要声称外仓已同步。

任务管理有真实需要时，按参考填实项目生命周期规则，由AGENTS明确要求相关任务执行前实际读取。活动任务只留目标、当前结论、下一步、验收与必要回滚；已验收任务移archive并同步引用，必要历史单独标类别且按需读取。压缩前先验证来源保留与敏感隔离，不逐轮追加日志、创建快照或把任务过程复制到资产/CHANGELOG。

### 4. 验收与交付

执行 [验收清单](references/migration-checklist.md)，检查内容保留、本地链接/锚点、导入环、frontmatter、Git 可见性、敏感信息隔离、重复执行幂等性；涉及任务资料时检查状态/位置、完成验收、历史类别与记录密度。检查器必须用一个已知坏输入证明会失败；明确检查范围和盲区。

纯文档迁移不强行跑业务全套测试；修改脚本/hooks/CI 则运行相关验证，并证明门禁能报错。不启动服务或触碰真实在线资源来验证目录布局。

输出：最终目录/职责、迁移映射、冲突处置、真实运行的验证、未验证的工具发现行为、未提交文件、外部兼容缺口与后续动作。默认不 commit、push、merge、tag、发布或部署。

## 禁止事项

- 不覆盖已有 AGENTS/CLAUDE 或采用整目录替换；不按模板丢掉独有规则。
- 不将 permissions.allow、密钥、个人绝对路径复制到共享配置；发现凭据只报告文件与风险，不复述值。
- 不将已放行但仍未跟踪的文件称为“已随 clone 分发”。
- 不把角色当持久团队成员、把 skills 当规则、把 memory 当源码事实、把静态验证当运行验证。
- 不为漂亮目录预建空角色/规则/技能，不迁移业务项目或部署资产，除非另获授权。
